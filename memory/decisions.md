# 技术决策记录

## 2026-05-19：使用 Qt Widgets 作为 UI 技术

### 决策

先使用 Qt Widgets，而不是 Qt Quick / QML。

### 原因

- Qt Widgets 对 C++ 初学者更直接
- 控件、窗口、布局和信号槽都能用 C++ 代码清楚表达
- 适合先学习桌面软件的基础结构
- 项目前期更容易做出登录窗口、聊天窗口、好友列表等界面

## 2026-05-19：使用 CMake 作为构建系统

### 决策

使用 CMake 管理 C++ / Qt 工程。

### 原因

- Qt 6 官方推荐 CMake
- 便于理解真实 C++ 工程如何组织
- 后续可以同时管理客户端和服务器两个程序

## 2026-05-19：使用 VS Code 作为主要 IDE

### 决策

项目开发主要使用 VS Code。

### 原因

- 用户已经习惯 VS Code
- VS Code 配合 CMake Tools 可以清楚看到 C++ 工程的构建过程
- 有利于学习 CMake、编译器、Qt 路径和工程结构，而不是完全依赖 Qt Creator 自动配置

## 2026-05-19：当前 Qt 安装使用 MinGW 版

### 决策

当前先使用已安装的 Qt 6.11.1 `mingw_64` 套件。

### 原因

- 本机已经安装 `C:\Qt\6.11.1\mingw_64`
- Qt 同时安装了匹配的 MinGW 13.1.0、CMake 和 Ninja
- 这套工具链可以直接用于 VS Code + CMake 项目

### 注意

MinGW 版 Qt 应该搭配 Qt 自带的 MinGW 编译器使用，不要和 MSVC 编译器混用。

## 2026-05-20：阶段完成后提醒提交 Git

### 决策

每完成一个清晰阶段，先提醒用户当前适合提交，再由用户确认是否执行 `git commit`。

### 原因

- 保持学习项目历史清楚
- 避免在用户未确认时创建提交
- 方便后续推送到 GitHub 和回看每个学习阶段的变化

## 2026-05-19：先使用 TCP，再考虑更高级协议

### 决策

网络通信先从 `QTcpSocket` 和 `QTcpServer` 开始。

### 原因

- TCP 是理解聊天软件通信的基础
- Qt 对 TCP 封装较好，适合学习
- 后续可以在 TCP 之上设计 JSON 消息协议
